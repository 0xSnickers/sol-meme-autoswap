## 本次策略升级

### 1. 增加总资金账户模型

之前的链上模拟交易已经有:

- 信号
- 交易评分
- 开仓
- 止盈止损
- 已平仓结果

但还缺一层关键风控:

- 总账户资金限制

这次新增的账户口径是:

- `总资金 = 1000 USD`
- `已用资金 = 当前打开持仓买入成本之和`
- `可用余额 = 1000 + 已实现盈亏 - 当前打开持仓成本`
- `账户权益 = 可用余额 + 当前持仓市值`

这样系统不再是“只要信号通过就继续开仓”，而是会受到真实可用现金约束。

### 2. 同一轮信号按优先级分配资金

如果一轮扫描里出现多个可交易信号，这次不再按出现顺序开仓，而是按以下顺序优先分配资金:

- `tradeScore` 高的优先
- `聪明钱` 多的优先
- `动量涨幅` 更强的优先

这样更符合真实交易场景:

- 先给高质量信号分配仓位
- 余额不够时，自动放弃低优先级候选

### 3. 余额不足直接拒绝开仓

当前如果某个候选信号满足交易条件，但:

- 预计开仓金额 `>` 当前可用余额

则该笔交易会被记录为:

- `rejected`
- 原因写入 `可用余额不足`

这一步很重要，因为后面接 GMGN 真仓时，真实账户一定也会遇到这个问题。

## 页面展示升级

### 1. 双列布局

页面中的:

- `持仓中`
- `已平仓`

现在改成同一行两列展示，不再纵向堆叠。

这样做的目的:

- 左边看正在承受的风险
- 右边看已经兑现的结果
- 不需要上下滚动来切换两个区域

### 2. 卡片式持仓列表

每条持仓不再是传统表格行，而是卡片展示，重点突出:

- Token 名称
- CA 复制
- 买入金额
- 当前市值 / 卖出金额
- 买入价 / 当前价 / 卖出价
- 持仓数量
- 总盈亏
- 信号次数和交易评分

### 3. 分区汇总

为了方便你快速判断当前状态，这次在分区顶部直接显示:

#### 持仓中

- 买入总金额
- 当前总市值
- 浮动总盈亏

#### 已平仓

- 累计买入
- 累计卖出
- 已实现总盈亏

这比只看单个持仓更接近真实交易面板。

## 这版的意义

这次升级最重要的不是 UI 变化，而是系统正式具备了更接近真实账户的执行逻辑:

- 有总资金
- 有可用余额
- 有资金占用
- 有账户权益
- 有持仓区和已实现区

这意味着后面如果要接 GMGN 自动交易，核心执行链路已经更完整了。

# 策略复盘 2026-05-01 10:40

## 当前策略现状

当前代码里的真实信号规则是:

- 扫描范围: 仅 `SOL`
- 扫描频率: 每 `30s`
- 动量触发:
  - 最近连续 `3` 轮市值上涨
  - 总涨幅 `>= 5%`
- 质量门槛:
  - `聪明钱 >= 2`
  - `流动性 >= 3000`
  - `持有人 >= 50`
  - `1h 成交量 >= 10000`
  - `买卖比 >= 1.1`
  - 至少有 `1` 个社交或官网链接
- 安全检查:
  - `SOL` 走 `RugCheck`
- 信号持久化:
  - 已记录信号出现次数
  - 已记录每次信号时间
  - 已记录每次信号出现时的价格

这套规则的优点是:

- 信号比较干净，不会因为纯叙事就触发
- 已经有一定的流动性和持仓结构过滤
- 已经适合做“可回放”的半自动系统

这套规则的不足也很明显:

- 现在的“推送信号”还不等于“适合买入的交易信号”
- `聪明钱 >= 2` 只是最低门槛，不足以决定仓位
- “出现次数越多”不一定越适合买，很多时候代表已经走了一段
- 只有固定的触发条件，没有分层买入逻辑
- 如果后面直接“每次信号都自动买”，会非常容易买在延续末端

## 你当前想法的问题

你现在的想法是:

- 一旦检测到信号就自动调用 GMGN 买入
- 涨幅大于 `20%` 自动卖出

这个逻辑很直观，但有几个风险:

### 1. 每次信号都买入，容易追高

因为你的信号本质上是“连续上涨确认后”的追涨信号。

这意味着:

- 第 `1` 次信号可能是刚形成趋势
- 第 `2`、`3`、`4` 次信号很可能已经进入加速后半段

如果不区分“第几次信号”，你可能会:

- 第一次买到趋势起点
- 第二次继续加仓
- 第三次、第四次买在局部顶部附近

### 2. 固定 `20%` 止盈过于单一

固定止盈有一个问题:

- 强币可能不止涨 `20%`
- 弱币可能连 `20%` 都到不了，反而先回撤

如果只有一个 `+20% 全卖`，你会遇到:

- 强趋势吃不满
- 假突破没有止损保护

### 3. 没有止损规则，自动交易风险过大

如果你只定义了止盈，没有定义止损，自动买入会暴露出最大问题:

- 买错之后不知道什么时候退出
- 一旦流动性塌陷，很容易回撤远大于你的预期

### 4. 聪明钱数量不能单独决定是否交易

`smart_degen_count` 有价值，但不能单独作为开仓依据。

同样是 `聪明钱 = 4`:

- 有的币是早期低位刚启动
- 有的币已经高位拉升多轮

所以聪明钱更适合做:

- 评分因子
- 仓位因子
- 是否允许加仓的因子

不适合做唯一决策条件。

## 更合适的思路

建议你把系统分成两层:

- 第 1 层: `信号层`
- 第 2 层: `交易层`

也就是说:

- 不是“有信号就买”
- 而是“有信号后，再判断这个信号值不值得买”

## 建议的交易决策模型

### 一. 信号继续沿用当前雷达

当前雷达用于“发现候选交易机会”，这个方向是对的。

先不要把当前信号层废掉，只需要在信号层之上叠加交易层即可。

### 二. 增加交易评分

建议每次信号触发后，再计算一个 `tradeScore`。

推荐参考以下因子:

- `聪明钱数量`
- `信号出现次数`
- `流动性`
- `1h成交量`
- `买卖比`
- `币龄`
- `是否有 X / TG / 官网`
- `最近 1h 涨幅是否过热`

### 三. 推荐的评分思路

可以先用简单打分，不要一开始做太复杂。

```text
基础分 0-100

聪明钱:
- >= 8  -> +30
- 5-7   -> +24
- 3-4   -> +16
- 2     -> +8

信号次数:
- 第1次 -> +20
- 第2次 -> +12
- 第3次 -> +4
- >=4次 -> -8

流动性:
- >= 20000 -> +18
- >= 10000 -> +12
- >= 5000  -> +6

1h成交量:
- >= 100000 -> +15
- >= 50000  -> +10
- >= 20000  -> +6

买卖比:
- >= 1.5 -> +10
- >= 1.3 -> +7
- >= 1.1 -> +4

过热惩罚:
- 1h涨幅 >= 80% -> -20
- 1h涨幅 >= 50% -> -12
```

然后分档:

- `score >= 70`: 允许自动买入
- `55-69`: 只观察，不自动买
- `< 55`: 只记录信号

## 关于“信号次数”的建议

你的问题里最值得单独强调的就是“信号出现次数”。

我建议不要把“次数越多越好”。

更合理的是:

- `第1次信号`
  - 最值得关注
  - 如果质量高，优先买
- `第2次信号`
  - 可以买，但仓位应低于第1次
- `第3次及以上`
  - 默认不追
  - 除非聪明钱明显提升，且流动性/成交量同步放大

原因很简单:

- 多次信号说明趋势延续
- 也说明价格离起点越来越远
- 自动交易最怕在趋势尾部不断追买

### 推荐规则

- 第 `1` 次信号: 可开主仓
- 第 `2` 次信号: 只允许小仓或不加仓
- 第 `3` 次及以上: 默认禁止新开仓

除非同时满足:

- `聪明钱 >= 6`
- `流动性 >= 15000`
- `1h成交量 >= 50000`
- `买卖比 >= 1.3`

## 关于“聪明钱数量”的建议

建议把聪明钱用于“仓位调整”，而不是只用于“是否通过”。

### 推荐做法

- `聪明钱 2`
  - 只允许试仓
- `聪明钱 3-4`
  - 可正常仓位
- `聪明钱 5-7`
  - 可提高仓位
- `聪明钱 >= 8`
  - 可列为高优先级

### 推荐仓位映射

```text
聪明钱 = 2      -> 0.25R
聪明钱 = 3-4    -> 0.50R
聪明钱 = 5-7    -> 0.75R
聪明钱 >= 8     -> 1.00R
```

这里的 `R` 是你定义的标准风险单位，例如:

- 每笔最多亏总资金的 `1%`

## 关于卖出逻辑

单一的 `+20% 自动卖出` 可以作为第一版，但我不建议作为最终版。

### 更好的第一版

建议至少改成:

- `止损`: `-8%`
- `止盈1`: `+15%` 卖出 `40%`
- `止盈2`: `+25%` 再卖出 `40%`
- 剩余 `20%` 使用追踪止盈

这样有几个好处:

- 不会完全吃不到大趋势
- 也不会因为贪心没有落袋
- 有明确止损，风险更可控

### 如果你坚持先做极简版

极简版建议至少也要变成:

- `买入后 -8% 止损`
- `买入后 +20% 全卖`

不要只做 `+20% 卖出` 而不做止损。

### 平仓条件

- `-8%` 止损
- `+20%` 止盈

### 暂时不要做的事

- 不要对同一 Token 连续无限加仓
- 不要因为第 `3` 次、第 `4` 次信号继续追单
- 不要让页面刷新直接触发交易

## 为什么我建议这样做

核心原因是:

- 你现在的系统已经是一个“不错的发现系统”
- 但还不是一个成熟的“自动交易系统”

发现系统追求:

- 抓到机会

自动交易系统追求:

- 风险收益比
- 仓位控制
- 避免重复追高
- 可回放可审计

所以最合理的路径不是直接“信号 -> 交易”，而是:

```text
信号 -> 评分 -> 风控 -> 交易
```

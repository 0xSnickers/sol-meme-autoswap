# 当前策略与实现说明

这份文档用于说明当前项目到底在做什么、怎么做、做到哪一步了。

适合在你回看项目时快速回答 3 个问题：

- 当前策略怎么触发信号
- 当前链上模拟交易怎么开仓和平仓
- 当前前端页面和后端数据是怎么串起来的

## 1. 项目当前定位

当前项目不是实盘交易系统，而是一个 `SOL Meme signal scan + 链上模拟交易 + 前端看板` 系统。

它的目标是：

- 从 GMGN 拉取 `SOL` 新币和热门候选
- 用动量规则筛选出值得关注的 Meme
- 用更严格的交易评分和风控规则决定是否纸上开仓
- 用 `SQLite` 持久化历史信号、交易意图、持仓和已平仓结果
- 用 `Supabase` 同步快照、持仓、推送信号和运行态数据
- 在 Next.js 页面里实时展示账户、持仓、已平仓和推送 Token

一句话概括：

> 现在项目已经从“只看信号”进化到“能持续复盘的链上模拟交易面板”，但还没有进入真实下单阶段。

## 4. 当前扫描范围和基础参数

当前策略已经切到一版更保守的 `v1.2 风控收紧版`。

### 扫描层

- 只扫描 `SOL`
- 扫描间隔：`30s`
- 候选来源：
  - 按 `open_timestamp` 排序的 1h swaps
  - 按 `swaps` 排序的 1h swaps
- 候选数量：
  - 第一组 `limit=100`
  - 第二组 `limit=50`

### 候选过滤

- 最小市值：`1000`
- 最大市值：`10,000,000`
- 最小基础流动性：`500`

### 推送层门槛

- 最小聪明钱：`2`
- 最小流动性：`3000`
- 最小持有人：`50`
- 最小 1h 成交量：`10000`
- 最小买卖比：`1.1`
- 默认要求至少有一个社交/官网链接

## 5. 当前信号逻辑

当前项目的核心不是“叙事驱动”，而是“动量驱动”。

叙事只负责分类展示，不决定是否推送。

### 当前触发条件

- 连续 `3` 轮上涨
- 累计涨幅 `>= 5%`
- 满足推送层的质量过滤

### 当前推送逻辑本质

- 有动量，才可能推送
- 有叙事，不等于推送
- 叙事只作为标签出现在 UI 和消息里

### 当前叙事分类

- `★★★` 马斯克 / 川普
- `★★★` 币安 / CZ
- `★★` 名人 / 热点
- `★` 无明确叙事

## 6. 单轮扫描流程

```mermaid
flowchart TD
    A[拉取 SOL 候选币] --> B[过滤市值和基础流动性]
    B --> C[更新 momentum tracker]
    C --> D{是否满足 3 轮连涨且涨幅 >= 5%}
    D -- 否 --> E[继续观察]
    D -- 是 --> F[检查聪明钱 / 流动性 / 持有人 / 成交量 / 买卖比 / 社交链接]
    F -- 不通过 --> E
    F -- 通过 --> G[生成推送信号 alert]
    G --> H[写入 pushed_alerts]
    G --> I[进入交易评分与风控]
```

## 7. 当前交易层逻辑

当前交易层和推送层是分开的。

也就是说：

- 一个币可以被推送很多次
- 但不一定会被买入

### 交易层的核心思路

推送解决“值得看”

交易解决“值不值得买”

### 当前开仓门槛

- `tradeScore >= 76`
- 只允许第 `1` 次信号开仓
- 最小聪明钱：`3`
- 最小流动性：`15000`
- 最小 1h 成交量：`30000`
- 最小买卖比：`1.4`
- Token 币龄：`<= 48h`

### 高热模式附加条件

当 `1h` 涨幅 `>= 50%` 时，不直接禁止开仓，但会切换到更严格的高热模式：

- `tradeScore >= 82`
- 聪明钱 `>= 6`
- 流动性 `>= 30000`
- 买卖比 `>= 1.6`

### 当前评分项

#### 当前评分核心

- `smart money` 仍然重要，但权重已经下调，不再单独决定高分
- 越早的信号，加分越高
- 流动性越高，加分越高
- 1h 成交量越高，加分越高
- 买卖比越高，加分越高
- 币龄越早，加分越高

#### 当前扣分项

- `buySellRatio` 低于健康区间会被扣分
- `1h` 涨幅过热会被扣分：
  - `>= 30%` 开始扣分
  - `>= 50%` 扣分更明显
  - `>= 80%` 大幅扣分并进入高热模式

#### 额外说明

- 当前评分不再像旧版那样过度偏向 `smart money`
- 现在更强调 `liq + volume + buy/sell ratio + 热度控制`
- 目的不是抓更多票，而是减少“表面很热、实际承接不足”的误开仓

## 8. 当前纸上账户风控

当前纸上账户是固定资金模型，不是无限开仓。

### 账户参数

- 总资金：`1000 USD`
- 基础仓位：`40 USD`
- 最多打开持仓：`4`
- 资金使用率上限：`25%`

### 仓位大小

实际仓位不是固定 `40 USD`，而是根据 `tradeScore` 为主、`聪明钱` 为辅动态调整。

大致逻辑：

- `tradeScore 76-79`：`0.7x`，约 `28 USD`
- `tradeScore 80-84`：`1.0x`，约 `40 USD`
- `tradeScore >= 85`：`1.2x`，约 `48 USD`
- 聪明钱 `>= 8` 且 `tradeScore >= 80`：可微调到上限档

所以真实仓位会主要落在 `28 / 40 / 48 USD` 三档，而不是所有币都同样重仓。

## 9. 当前开仓到平仓的流程

```mermaid
flowchart TD
    A[推送信号 alert] --> B[计算 tradeScore]
    B --> C{是否满足开仓门槛}
    C -- 否 --> D[写入 trade_intents: rejected]
    C -- 是 --> E{是否已有同币打开持仓}
    E -- 是 --> F[写入 trade_intents: skipped]
    E -- 否 --> G{是否超过最大持仓数}
    G -- 是 --> D
    G -- 否 --> H{是否超过资金使用率上限}
    H -- 是 --> D
    H -- 否 --> I{可用余额是否足够}
    I -- 否 --> D
    I -- 是 --> J[写入 paper_positions: open]
    J --> K[每轮扫描更新 current_price / peak_price]
    K --> L{达到分批止盈?}
    L -- 是 --> M[执行 TP1 / TP2，保留尾仓]
    L -- 否 --> N[继续检查退出条件]
    M --> N
    N --> O{触发 SL / Trailing / Time Stop?}
    O -- 否 --> P[保持 open]
    O -- 止损 --> Q[关闭持仓: stop_loss]
    O -- trailing --> R[关闭持仓: trailing_stop]
    O -- 时间止损 --> S[关闭持仓: time_stop]
```

## 10. 当前止盈止损逻辑

- 止损：`-25%`
- 第一止盈：`+25%` 卖出 `55%`
- 第二止盈：`+60%` 卖出 `25%`
- 第三止盈：`+120%` 卖出 `20%`
- 时间止损：持仓超过 `6h` 且仍未达到第一止盈，直接平仓
- Trailing：涨到 `+35%` 后启动；若从峰值回撤 `15%`，平掉剩余仓位

每一轮扫描会检查所有打开中的 `paper_positions`：

- 如果最新价格达到某一档 `TP`，按原始总仓位比例分批卖出
- 如果最新价格 `<= SL` 价格，平仓
- 如果已启动 trailing 且价格跌破 trailing stop，平仓
- 如果超过时间止损仍未达到第一止盈，平仓
- 否则只更新浮动盈亏

当前仍然没有：

- 手动加仓
- 手动减仓
- KOL 收藏加分
- Top 10 holders 集中度硬过滤

## 11. 当前数据库里保存了什么

### `pushed_alerts` / `radar_alerts`

保存每一次真正触发的推送信号。

用途：

- 前端展示推送列表
- 统计某个 Token 出现过几次
- 记录每次信号时的价格和时间

### `trade_intents`

保存每一次“是否应该开仓”的判定结果。

当前主要存在于本地 `SQLite` 运行模式中。

用途：

- 看某个币为什么没买
- 看被拒绝的原因
- 做后续策略复盘

### `paper_positions` / `radar_positions`

保存纸上持仓。

用途：

- 看当前打开持仓
- 看已平仓结果
- 计算账户权益、浮动盈亏、已实现盈亏

### 运行态元数据

保存运行态元数据。

用途：

- 最近扫描时间
- 当前策略 session 启动时间
- 策略已运行多久
- 当前 paper trade 设置
- 动量追踪和打开仓位运行态

## 12. 当前前端页面展示逻辑

前端不是直接扫链，而是通过两个接口拿数据。

### `/api/signals/snapshot`

用途：

- 拉取最新持久化快照
- 不负责触发主扫描
- 主扫描由独立 `signal worker` 执行

### `/api/signals/stream`

用途：

- 用 `SSE` 每 `5s` 推送一次实时快照
- 前端用它更新价格、账户权益和持仓状态

### 当前页面重点

顶部：

- 策略已运行多久
- 策略启动时间
- 实时连接状态
- 最近实时更新时间
- 最近扫描时间

中间统计：

- 账户权益
- 可用余额
- 打开持仓
- 资金使用率
- 浮动盈亏
- 已实现盈亏
- 推送数

下方：

- `持仓中`
- `已平仓`
- `推送 Token`

## 14. 当前项目处于什么阶段

当前项目处于：

> `信号系统 -> 交易打分 -> 纸上执行 -> 前端复盘`

这个阶段。

它已经不是“原型 demo”，但也还不是“真实自动交易系统”。

更准确地说，它现在是一个：

> 可以持续跑、可以持续观察、可以持续调策略的链上模拟交易实验平台。

## 15. 当前版本最重要的理解

你现在要区分 4 层：

### 第 1 层：候选层

从 GMGN 拉回来的所有候选 Meme。

### 第 2 层：推送层

满足动量和质量门槛，值得出现在你面前。

### 第 3 层：交易层

满足 tradeScore 和风控，才允许开仓。

### 第 4 层：复盘层

把推送、意图、持仓、盈亏全都存下来，方便你调策略。

如果你看到一个币“出现了很多次但没买”，通常不是 bug，而是：

- 它通过了推送层
- 但没有通过交易层

## 16. 你接下来应该重点看什么

如果你的目标是继续优化策略，优先看这几项：

- 哪些币被频繁推送但长期不买
- 哪些币开仓后最常因什么原因平仓
- `tradeScore >= 76` 是否仍然偏松
- `TP +25% / TP2 +60% / TP3 +120% / SL -25%` 是否合理
- trailing stop 是否太紧或太松
- `6h` 时间止损是否过早或过晚
- 最大持仓数和资金使用率是否还需要继续收紧

## 17. 后续建议路线

建议按这个顺序继续演进：

1. 继续跑纸上账户，观察足够多样本

3. 加入更细的风险指标
4. 接入 KOL 收藏和集中度数据
5. 最后再考虑接入真实交易
